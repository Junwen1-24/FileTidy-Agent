# FileTidy Agent 产品需求文档（MVP）

> 版本：0.1  
> 状态：MVP 实施版  
> 更新日期：2026-08-05

## 1. 产品概述

FileTidy Agent 是一个本地优先的个人文件整理助手。它扫描用户明确选择的目录，依据文件类型、名称、所在目录和最近修改时间生成可解释的标签与归档建议。用户确认后再执行真实移动，并可从操作记录中撤销。

产品不追求“自动替用户做决定”，而是通过“扫描—解释—确认—执行—可撤销”的闭环，降低整理桌面、下载目录和项目资料时的判断成本与误操作风险。

## 2. 用户与核心场景

### 2.1 目标用户

- 桌面、下载目录长期堆积文件的知识工作者。
- 同时处理多个项目，需要快速判断文件归属的人。
- 希望使用自动分类，但对误删、误移动和隐私上传敏感的个人用户。

### 2.2 核心场景

用户打开 FileTidy Agent，选择一个本地目录并扫描。系统展示文件清单，为每个文件给出类型、活跃度、项目等建议标签和理由。用户可修改或批量确认标签，预览目标位置，再执行移动；若结果不符合预期，可在操作记录中撤销。

## 3. 产品目标与非目标

### 3.1 MVP 目标

1. 首次启动无需外部服务即可体验完整流程。
2. 扫描结果来自真实文件系统，而非静态样例。
3. 标签、设置和操作记录在刷新或重启后仍然存在。
4. 文件移动前有预览，移动后有记录且可以撤销。
5. 核心操作有加载、成功、错误与空状态反馈。

### 3.2 MVP 非目标

- 云端 AI 内容理解、OCR、全文索引或向量检索。
- 重复文件检测、自动删除、清空废纸篓。
- 操作系统级“最近打开次数”、Finder/Explorer 原生标签同步。
- 后台定时扫描、系统托盘、登录启动。
- 多用户、账号体系、云同步、团队协作。
- 桌面安装包、Windows/Linux 适配与应用商店发布。

## 4. 用户故事

1. 作为用户，我可以输入本地目录路径并触发扫描，以便知道目录里有哪些文件。
2. 作为用户，我可以看到每个建议标签的判断依据，以便决定是否信任它。
3. 作为用户，我可以编辑或批量确认标签，以便保留自己的判断。
4. 作为用户，我可以按名称、标签和状态筛选，以便聚焦待处理文件。
5. 作为用户，我可以在移动前检查来源和目标，以避免意外整理。
6. 作为用户，我可以撤销一次整理，以便将文件恢复到原位置。
7. 作为首次体验者，我可以重置演示数据，以便重复演示核心流程。

## 5. 核心流程

1. 启动：首次启动自动复制演示文件到应用数据目录并扫描。
2. 选择目录：用户输入目录绝对路径；系统校验存在且可读。
3. 扫描：递归读取文件，忽略隐藏文件和符号链接，生成标签与去向建议。
4. 确认：用户选择文件，批量采纳建议，或直接编辑逗号分隔标签。
5. 预览：系统列出每个文件的相对来源和预计目标。
6. 整理：文件移动到根目录下的 `整理结果/<建议目录>/`，同名时增加序号。
7. 撤销：用户从操作记录恢复本次移动；原位置已被占用时阻止并解释原因。

## 6. 功能需求

### 6.1 目录设置与扫描（P0）

- 仅扫描用户输入的目录，不主动扩大权限范围。
- 校验目录存在、可读且为目录；失败时保持原设置。
- 默认最多扫描 1,000 个文件、8 层目录，可通过环境变量调整。
- 跳过隐藏项和符号链接；单个不可读文件不阻断全局扫描，并形成警告。
- 展示扫描时间、文件总数、待确认数、已确认数和需关注空间。

### 6.2 标签建议与确认（P0）

- 类型标签：文档、图片、压缩包、安装包、代码、其他。
- 活跃度标签：正在使用、常用、低频、可归档、长期闲置。
- 名称标签：截图、疑似临时。
- 目录标签：`项目:<一级目录名>`。
- 每个建议包含自然语言理由。
- 用户标签去重，单个最多 30 字符，每个文件最多 12 个。
- 支持选择多个文件并批量采纳建议标签。

### 6.3 筛选与状态（P0）

- 按文件名或相对路径搜索。
- 按标签筛选。
- 按待确认、已确认、已整理状态筛选。
- 无结果时提供空状态和恢复建议。

### 6.4 文件整理（P0）

- 仅允许移动当前根目录内的文件，目标也必须位于根目录内。
- 移动前展示来源、目标和数量。
- 按类型移动到 `整理结果`；截图进入 `图片/截图`。
- 目标同名时保留两份，新文件追加 `(2)`、`(3)` 等序号。
- 批量移动中途失败时尽力回滚本次已移动文件。
- 成功后持久化操作记录并更新文件路径。

### 6.5 撤销（P0）

- 一次整理作为一个原子操作展示。
- 撤销前验证整理后文件仍存在，且原位置没有同名文件。
- 撤销成功后恢复路径，更新文件状态和操作状态。
- 已撤销操作不可重复撤销。

### 6.6 演示模式（P0）

- 内置覆盖文档、图片、代码、临时文件和长期闲置文件的种子数据。
- “重置演示数据”只重建应用数据目录内固定的演示工作区。
- 重置后自动扫描，便于反复演示。

## 7. 规则说明

活跃度在 MVP 中以修改时间近似使用情况：7 天内为“正在使用”，8–30 天为“常用”，31–90 天为“低频”，91–180 天为“可归档”，超过 180 天为“长期闲置”。该规则不等同于操作系统真实打开频次，界面与 README 必须明确这一限制。

## 8. 数据模型

### Settings

- `rootPath`: 当前扫描目录绝对路径。
- `updatedAt`: 设置更新时间。

### FileRecord

- 标识与路径：`id`, `name`, `absolutePath`, `relativePath`, `extension`。
- 元数据：`size`, `sizeLabel`, `createdAt`, `modifiedAt`, `scannedAt`。
- 分类：`category`, `suggestions[]`, `confirmedTags[]`, `recommendation`。
- 状态：`organized`, `updatedAt`。

### Operation

- `id`, `type`, `status`, `createdAt`, `undoneAt`。
- `items[]`: `fileId`, `originalPath`, `targetPath`。

### ScanRun

- `id`, `completedAt`, `fileCount`, `warnings[]`。

数据存储为应用数据目录中的 JSON 文件，采用临时文件写入后重命名，避免写入中断留下半份 JSON。

## 9. 接口清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/state` | 获取设置、文件、摘要和历史 |
| POST | `/api/settings` | 更新扫描目录 |
| POST | `/api/demo/reset` | 重置演示工作区 |
| POST | `/api/scan` | 重新扫描 |
| PATCH | `/api/files/:id/tags` | 保存单文件标签 |
| POST | `/api/files/bulk-confirm` | 批量确认建议标签 |
| POST | `/api/organize/preview` | 获取移动预览 |
| POST | `/api/organize/execute` | 执行真实移动 |
| POST | `/api/operations/:id/undo` | 撤销整理 |

## 10. 非功能要求

- Node.js 18.16+，默认不依赖数据库和第三方在线服务。
- 默认监听 `127.0.0.1`，不暴露到局域网。
- 页面在桌面和窄屏浏览器可用。
- 不存储 API Key、密码或文件正文到状态文件。
- 所有 API 错误返回可理解的中文提示。
- 核心规则与整理/撤销流程有自动化测试。

## 11. MVP 验收标准

- 按 README 从空数据目录启动后，自动出现 8 个演示文件。
- 刷新页面后，用户确认的标签仍然存在。
- 选择一个未整理文件，预览后执行，文件在磁盘中出现在建议目标位置。
- 操作记录出现对应动作；点击撤销后，文件回到原始位置。
- 无效目录、源文件丢失、撤销冲突等情况给出错误提示。
- `npm run verify` 的语法检查、静态检查、测试和构建全部通过。

## 12. 风险与后续方向

- 修改时间只能近似活跃度。后续桌面客户端可在用户授权后接入系统元数据。
- JSON 存储适合个人 MVP；文件量和操作并发提升后应迁移 SQLite。
- 浏览器无法提供原生目录选择和文件系统权限模型；后续可用 Tauri/Electron 封装并复用当前服务层。
- 内容型分类需要明确隐私策略后再引入本地模型或可选云模型。
